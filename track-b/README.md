# Track B: Index

Reads `queries.txt` (BOOL and PHRASE queries) and `docs.txt` (one document per line) from `/data` and writes `results.txt` to `/out`: for each query, the number of matching documents, the sum of their ids and the ten smallest ids.

56.35 s → 0.24 s (about 237×), 2.2 GB → 40 MB. No index is built: one parallel pass decides every BOOL query 1,024 documents at a time from bit-rows and a sorted log of the rarer terms' hits, and every phrase by checks at its rarest term.

Rust, standard library only. K 24.49 (box `sd-bench/B`, commit a129cda, b-68 on b-64; the lower of two seeds): T 0.238 s, M 39.9 MB, S 753, D 1 (no dependencies). Board: run-11f0e517f808 (commit c8760d4, the code of 5668086, before b-64 and b-68), K 23.15, T 0.279 s, our best board run.

Terms: K is the organisers' score combining T (run time), M (peak memory), S (lines of code) and D (dependencies) against the reference, higher is better; the box is our bench machine with the scoring machine's CPU; b-NN is one experiment in PERF.md; KNOWN = a textbook technique, OURS = our own design.

## Approach

The program reads `queries.txt` first. Every line is its own query (a line dedupe was 70 M of the parse's 110 M instructions; removing it took the VM's parse from 32 ms to 22.7 ms), and every term is interned straight into the table the pass later probes. That table uses a fixed-width multiplicative hash of the zero-padded term and open addressing, and doubles whenever it would pass a load factor of 1/3. Each 4-byte slot holds the term's id in its low 30 bits and the hash's top 2 bits, so a miss reads one cache line. A hash match is confirmed against the term's bytes, which are stored inline and zero-padded in a 32-byte entry: one more line, and one 32-byte compare with the zero-padded token. Each PHRASE line becomes one pattern with one anchor, its term with the lowest estimated document frequency. The binary links the C runtime statically (probe b-21), so no dynamic loader runs before main.

Under the spec's strict left fold, whether a document is in a BOOL query's result depends only on which of the query's terms the document contains, so the same fold over 64-bit words, one bit per document, decides 64 documents at once. A document can only be in R if it contains a term of the query's cover. The cover starts as the first term; each OR operand is added to it; an AND operand may replace the cover when its estimated document frequency is lower. Every query is listed, with its code inline, under each term of its cover. Its accumulator slot follows that list order, so the queries one term triggers have neighbouring accumulators. Before the pass, document frequencies are estimated on 64 evenly spaced windows covering 1/128 of the corpus, only to make those choices. The sample's 64 windows are spread over the worker threads. The terms are then renumbered in place in the term table: the BOOL terms first, and each group by descending estimated frequency, so the terms most tokens hit have neighbouring ids and their table entries and rows share cache lines. A BOOL term sampled in at least 1/64 of the sampled documents is dense (738 of 53,444 on seed 1), and the dense terms are the first ids. A query whose cover holds a dense term is folded in every chunk; every other query is listed under its cover's terms. The BOOL and phrase plans are built on two threads.

`docs.txt` is mapped read-only and cut into one line-aligned range per worker. Each worker tokenizes its documents as the spec defines (ASCII lower-casing, runs of `a-z0-9`), classifying 32 bytes at a time with AVX2 and cutting tokens where the token-byte mask changes, the starts and ends decoded as two masks (b-55), so no branch is taken per byte. Each token's bytes are then loaded once, lower-cased by setting bit 5, zero-padded to 32 bytes, and hashed as four 64-bit words at once, so no loop depends on the token's length. The next token's slot line is prefetched before the current token is probed (b-64). A token found in the table, if it is a dense term, sets the document's bit in that term's 16-word row for the current 1,024-document chunk; any other BOOL term is appended to the chunk's log as its key and the document's place in the chunk, a store with no read (b-68). Neither takes a branch: a sparse hit sets a bit in a dummy row, and a dense hit's log entry is written but not kept. The pass records only a document's anchor occurrences, each with its byte offset. At the end of the document, each anchor occurrence is a candidate for every phrase anchored on that term, whose anchor is its j-th term, confirmed by reading the doc's bytes around it: the non-empty pieces of the text from the anchor on, split at separators, are the doc's own tokens from the anchor on, and the pieces before it, split from the right, are the tokens before it, so each of the pattern's other terms is checked against the token at its offset from the anchor; a term equals a token when its bytes equal the token's up to ASCII case and end there (the term table's own test). A token is a maximal run of `a-z0-9` and every other byte separates, so this reads the same tokens the old per-token sequence held and decides exactly what it decided, without the 36.3 M pushes per run (b-56). Each phrase counts a document once. A phrase containing a term that occurs nowhere has an estimated frequency of 0 there, so it is anchored on that term and never checked.

When the chunk ends, the worker sorts its log by key with a two-pass LSD radix sort (stable, so each key's documents stay ascending), drops repeated (key, document) entries, and notes each key's span. It folds every every-chunk query, then walks the keys present and folds each query listed under them once (a per-chunk stamp skips a query already folded through another key), over the chunk's 16 words at once, with AND, OR and AND-NOT; a sparse operand's row is built from its span of the log, and the operator selects masks from a small table, so the fold takes no branch on it. On seed 1 the 12 workers fold 3.64 M (query, chunk) pairs in all, where the 64-document window folded 18.84 M. For each word with a match, found through a mask of them, the match count is the popcount, and the id sum is the word's base times that count plus the sum over k of popcount(word AND mask_k) shifted left by k, where mask_k selects the bit positions whose bit k is set. First ids are taken from the word only while the query can still use them, and offered to a shared set of the ten smallest ids, which a single atomic bound guards. Then the rows and spans are cleared. After the pass, the workers' counts and sums are added up. PHRASE answers are the per-document matches the pass collected. `results.txt` is formatted with a small decimal writer, each worker formatting one contiguous slice of the queries, and written once at the end, and the process exits right after, without freeing its tables.

None.

## With another 24 hours

- The chunk evaluation (b-68): most of its folds are of queries whose operands are all rare, with one to three documents in the chunk, so they spend 16-word work on a few bits; testing those documents one by one read slower on the VM, so a cheaper per-document form is what is left to find.
- The pass's table access: the one-token-ahead slot prefetch inside `walk` was the form left after b-58 and b-60, and it was kept (b-64: box T 0.268 → 0.250 s); a longer prefetch distance is unmeasured.
- An 8-byte accumulator that keeps the duplicate-fold stamp inside it (narrow fields that spill exactly on wrap), so the halved footprint does not cost an extra line per fold (b-33b moved the stamp out and lost).
